# 低分模式与避雷（论文专题3/4 + 总复习）

判分直觉：**不偏题的平庸稿 > 偏题的「技术深度」稿**。

## A. 致命偏题

| 模式 | 典型表现 | 正确做法 |
|------|----------|----------|
| Q2 答错题 | 题问高并发六手段，却写微服务优缺点/适用性 | 按题面列举项逐项给定义+适用点 |
| Q2 整段缺失 | 背景后直接「在本项目中…」实践 | **独立 Q2 专段**；无此段≈不及格 |
| Q3 挂空挡 | 写拆分/治理长文，却不出现题面关键词（缓存/异步/限流…） | 每段显式点题；问题→该手段→效果 |
| 论题替换 | 高并发题通篇微服务架构论；六边形题滑成 DDD 主线 | 可用微服务/DDD 作手段，但论题关键词必须当主角 |
| 主线发散 | 题要「一种架构风格」，摘要/正文并列四五种当主角 | 选定一种深入，或开篇立「以X为主的混合」并扣住 |
| 开头跑题 | 实践段先写长篇「单体 vs 微服务选型对比」 | 若题要落地手段，直接结合项目写怎么用 |
| 列举漏项 | Q2/Q3 只写 N 项中的一部分 | Q2 N 条一一对应；Q3 每项至少一次落地 |

## B. 模板味 / 形式违规

| 模式 | 典型表现 | 正确做法 |
|------|----------|----------|
| 技术栈账单 | 背景：`SpringCloud、Redis6.2.5、Kafka、ShardingSphere、ES…` | 技术嵌入句子；只展开与本题相关的 |
| 功能只点名 | 「优惠券、购票、商城、缴费、团购」一串 | 2–3 个核心模块写清干什么、为何相关 |
| 考试小标题 | 「项目背景介绍」「正文：」「子题目2」 | 自然段落；机试勿玩目录腔 |
| 纯条目无论述 | 通篇 1.2.3. 无场景故事 | 段落为主；段首主题词代替全局编号 |
| 摘要写团队 | 后半写「我所带团队负责 A/B/C」 | 后半点题 + 预告论述结构 |
| 摘要未点题 | 只有项目履历 | 后半必须出现论题关键词 |
| 背景逻辑跳 | 刚写痛点，下一句「历时×月已上线」无方案过渡 | 痛点→立项/方案→功能→职责→过渡入题 |
| 背景无功能 | 只有金额周期无业务模块 | 展开 2–3 个核心功能 |

## C. 深度与可信度问题

| 模式 | 典型表现 | 正确做法 |
|------|----------|----------|
| 一句话技术 | 「用了 K8s、反规范化、MQ 实现自动扩缩容」糊在一起 | 每手段：场景问题 + 做法 + 可感知效果 |
| 风格≈产品 | 把 B/S、MyBatis、Vue、Redis 称作「架构风格」 | 先风格（约束），再构件实现（产品/框架） |
| 技术张冠李戴 | 视频流子系统「用 Dubbo 实现」等硬伤 | 协议/RPC/存储各归其位；不确定就写保守准确表述 |
| 不足跑题 | 结尾只谈带宽、机房、断电 | 不足落到分层边界、量化不足、文档滞后、手段覆盖缺口等 |
| 无指标空效 | 「提升了性能」「用户满意」 | 尽量给 QPS、延迟、可用率、错误率、资源节省等 |

## D. 结构缺失（专题3 AI 批改高频）

- 有「正文」但**没有清晰的 Q2 理论知识/手段段**  
- 理论到实践**无过渡句** → 用「基于上述…结合本项目…决定采用…」  
- 混合风格未立论 → 像技术选型说明书，不像论题论文  
- 字数各块同时取上限 → 正文冲破 2500；应按档位压缩  

## E. 可借鉴的「刚过线 / 高分」特征

- **完全按论题写**：Q2 总述手段，Q3 按模块或手段结合项目，即使文笔一般也可过（约 47–48）  
- **摘要即提纲**：点题 + 与题面同序的三方面预告  
- **点题密度高**：段首或段中反复出现论题短语  
- **效果可核验**：可用性、QPS、P99、错误率下降等前后一致  
- **给分点加粗**：方便阅卷检索  

## F. 反例标签（阅卷口语，便于检索）

- 「模板化」— 罗列技术/功能、小标题腔  
- 「子题目2未回应」— 写了相关域但没答提问 / 无专段  
- 「子题目3偏题」— 项目故事精彩但关键词缺失  
- 「通篇列举一二三」— 无背景无结构  
- 「摘要未点题」— 只有项目履历  
- 「高并发写成微服务」/「六边形写成 DDD」— 论题被替换

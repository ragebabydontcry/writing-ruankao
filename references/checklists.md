# 审题 / 交稿自检 / 批改清单

## 审题清单（动笔前）

- [ ] 抄出完整论题标题与三个子题原文要点  
- [ ] 标出 Q2 是否含**强制列举项**（N 个方面必须都写）  
- [ ] 判定题型：风格类 / 手段类 / 方法类（ABSD 等）/ 过程类 / 工程类  
- [ ] 选定**唯一主论点**；若混合，写下开篇立论句  
- [ ] 映射表：`子题 | 题面关键词 | Q2 应答要点 | Q3 段首主题/模块`  
- [ ] 确认项目素材：金额、周期、模块、可写指标是否自洽  

## 交稿自检（write 模式必做）

### 子题三刀（一票否决）

- [ ] Q1：项目背景 + 本人**架构设计师**职责；功能有介绍  
- [ ] Q2：**独立专段**；题面要点/列举 **N 项全部出现**  
- [ ] Q3：每项手段/步骤落到**本项目模块 + 问题 + 效果**；段首点论题  

### 点题链与加粗

- [ ] 摘要后半点题，并预告与子题同序的结构  
- [ ] 背景末有过渡句导入本题  
- [ ] Q2 段首点题；实践每段段首点题；结尾呼应论题  
- [ ] Q2 要点名 / 关键指标 / 核心决策已加粗  

### 形式与字数

- [ ] 摘要 ≤300 字；无图/表；**物理一段**  
- [ ] 正文小计约 2200–2500（背景+Q2+实践+结尾）  
- [ ] Q2 约 350–450 字（列举可至 500）  
- [ ] 实践约 3 段、合计约 1000–1200 字  
- [ ] 无「项目背景介绍」「子题目2」等考试模板小标题  
- [ ] 无通篇全局 1.2.3.；单位名已匿名（某…）  

### 质量

- [ ] 无技术栈账单式罗列  
- [ ] 未把框架/中间件误称为架构风格（风格类题）  
- [ ] 手段类每段有指标/效果；风格类有构件/连接件/约束语言  
- [ ] 结尾不足与论题相关，且非致命事故  
- [ ] 前后数字（金额、周期、人数、指标）一致  
- [ ] **列举/过程题：Q2 全覆 N 项，且 Q3 均有对应落地**  

## 批改四维（review；须先过三刀）

对每维给出：`严重|中等|轻微` + 证据句 + 改法。

### 1. 审题与内容

- 论题要求的「种/方面」是否被偷换成别的主题？  
- 列举 N 项是否漏项？  
- 混合论述是否缺少显式主线？  
- 实践段是否变成纯产品说明书或选型心路？  

### 2. 结构与衔接

- 是否具备：摘要 / 背景 / **Q2 专段** / 实践≥3 段 / 结尾？  
- 点题链是否完整？理论→实践是否有过渡？  

### 3. 技术准确性

- 风格 vs 框架混淆？  
- 协议/RPC/存储/扩容等表述是否硬伤？  
- 一句话塞多个无关技术？  

### 4. 语言与逻辑

- 口语、超长段、错别字？  
- 模板味、罗列症、教学小标题？  
- 不足是否跑题到基础设施？  

**输出顺序：** 三刀否决 → 致命偏题/漏项 → 结构 → 技术硬伤 → 语言润色。  
五维权重定义见 `scoring-rubric.md`。

## 表达自检（表达 15%）

- [ ] 无口语化  
- [ ] 实践段不过长（建议 ≤450 字/段）  
- [ ] 段首主题词清晰，非全局编号答题  
- [ ] 摘要未物理分段  

## 考场时间盒（练写/提示用户时）

1. 0–10 min：审题 + 映射表 + 定主论点  
2. 10–25 min：摘要 + 背景  
3. 25–90 min：Q2 + Q3 主体  
4. 90–110 min：结尾调字数（正文落在 2200–2500）  
5. 110–120 min：三刀打勾 + 加粗给分词 + 通读  

## ABSD / 方法类附加检查

- [ ] 出现需求（含质量属性）驱动设计  
- [ ] 有架构文档/规格或等价沟通产物  
- [ ] 有评审/复审控制风险  
- [ ] 有演化/变更应对  
- [ ] 不足落在度量、文档滞后、治理成本等，而非无关运维

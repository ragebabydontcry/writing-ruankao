# 系统架构设计师论文写作方法总结（2026年10月蒸馏）

> 蒸馏自：总复习资料（主源）+ 论文专题1-2 / 专题3 / 专题4。  
> 用途：考场默写与 Agent Skill（writing-ruankao）权威方法。  
> 冲突取舍见文末「默认裁决」。

## 1. 核心原则

**不偏题 > 技术炫技。**  
一般但不偏题可过；技术多但子题错位常低分（约 34–40）。  
子题2 整段缺失 ≈ 不及格；子题3 须写「在该项目中如何做」。

## 2. 双轨评分（Agent 两阶段门禁）

**顺序强制：先子题三刀切全部打勾，再对照五维润色。** 三刀任一未过，不得宣称可交稿。

### 2.1 写前 / 自检：子题三刀切（专题4）

| 子题 | 问什么 | 写到哪里 | 硬门槛 |
|------|--------|----------|--------|
| Q1 | 项目、角色、主要工作 | 摘要前半 + 背景全文 | 功能要有介绍；技术写清用途 |
| Q2 | 理论 / 过程 / 列举 N 项 | **独立一段**（背景后、实践前） | **必须有专段回应** |
| Q3 | 落地、问题、效果 | 正文 3 段为主 | 段首点论题；覆盖 Q2 要点 |

### 2.2 润色：官方五维

| 维度 | 占比 | 写作含义 |
|------|------|----------|
| 贴合题意 | 30% | 子题全覆盖、关键词对齐 |
| 深度与水平 | 20% | 架构师取舍与判断 |
| 实践性 | 20% | 像真做过（模块/场景/指标） |
| 表达能力 | 15% | 逻辑流畅、段落清晰 |
| 综合分析 | 15% | 问题—方案—效果—不足闭环 |

## 3. 字数与结构（默认裁决）

### 3.1 统计口径（必须先读）

- **摘要**：机考**单独输入框**，≤300 字，**不计入正文**。  
- **正文**：机考正文框 = **背景 + Q2 + 实践 + 结尾**。  
- **过渡**（约 80–150 字）**并入**背景末或 Q2 末，**不得与上列块重复加计**。  
- **全文（含摘要）** ≈ 摘要 + 正文；备考口算常用「摘要 300 + 正文约 2200」。  
- **正文目标区间：2200–2500**（与机考正文框一致）；写作取中位约 **2300–2400**。

### 3.2 默认字数表（正文各块）

| 块 | 目标字数 | 说明 |
|----|----------|------|
| 摘要（另框） | ≤300（目标≈280） | **物理一段**；逻辑含「履历+点题」两层 |
| 项目背景 | 500–600 | 含末段过渡时取上限附近；主体可万能 |
| Q2 理论/手段 | 350–450 | **单独成段**；列举题可至 **500**（见 §9「Q2 列举题字数」） |
| 实践 Q3 | 1000–1200 | 约 3×330–400；不可万能 |
| 结尾 | 350–450 | 字数调节阀（不够写到 500，超了先压结尾） |
| **正文小计** | **2200–2500** | 背景+Q2+实践+结尾；过渡不另计 |

**与主源「主体 1200」的关系：**  
- **紧凑档（主源口算）**：Q2 + 实践 ≈ 1200（如 Q2 300–400 + 实践 800–900），正文靠背景+结尾凑满 2200。  
- **默认档（本总结 / Skill）**：Q2 + 实践 ≈ **1400–1600**（Q2 350–450 + 实践 1000–1200），背景与结尾取中低位，使**正文小计落在 2200–2500**。  
- **冲刺档（专题3 十段式上限）**：实践可到 1500，此时必须压缩背景/结尾，禁止各块同时取上限。

可提前默写约 1200 字：摘要 + 背景主体 + 结尾框架（**不是**紧凑档「Q2+实践≈1200」）。

### 3.3 十段式 ↔ 五块（写作时不写章节标题）

1. 摘要（1 段，另框）  
2–3. 背景：缘由 / 周期·职责·功能·技术（含过渡）  
4. **Q2 专段**（可含向实践的过渡句）  
5–7. 实践 3 段（理论一句 + 在本项目中 How + 效果）  
8–9. 结尾：上线效果呼应论题 / 小不足+纠偏+提升  

**禁止**正文出现「摘要」「项目背景介绍」「子题目2」等教学小标题。

## 4. 各块写法

### 4.1 摘要

- 要素：时间 + 项目 + 简介 + 投入 + 历时 + 交付评价 + **论题与结构预告**  
- 后半必须一眼看出论题关键词（高并发勿写成微服务论；六边形勿滑到 DDD）  
- 句式示例：「本文结合作者的实践，以…项目为例，讨论…，包括…」/「在本文中，首先…，然后…，最后…」  
- 勿：团队分工流水账、功能模块逐条罗列撑爆 300 字、摘要分段

### 4.2 项目背景

- 段1：为何做（痛点、决策）  
- 段2：立项/角色/金额周期；**2–3 个核心功能展开**；技术嵌入用途叙述（禁栈清单）  
- 末句过渡：「于是笔者决定在……方面……，下文首先阐明……，再结合本项目论述……」  
- 口径：近 3–5 年、≥6 月、已上线；某市/某医院；金额约 500 万量级；角色=**系统架构设计师**；内部项目不写「内部」

### 4.3 Q2（理论 / 手段 / 过程）

- **单独成段**，问什么答什么  
- **列举 / 过程硬规则**：题面写「简述 A/B/C…」或「从以下 N 方面」时，Q2 **必须 N 条一一对应**（可用**加粗**项名）；**禁止合并省略导致少于 N**；随后 Q3 **每一项至少一次**「在本项目中…」落地（可按模块组织，但须有映射可核对）  
- 过程题：按题面步骤写全（如六边形：分析、设计、实现）  
- 风格题：先列风格含义，再定**一种主线**深入（混合须开篇立论）  
- 过渡模板：「基于对上述…的分析，结合本项目在…方面的核心需求，我们决定采用…。以下从三个方面展开论述。」

### 4.4 Q3（实践）

- 每段：**段首点论题关键词** → 本项目模块/场景问题 → 手段做法 → **可核验指标**  
- 覆盖 Q2 的同一组手段/步骤（N 项映射），勿换成另一套话题  
- 一项技术一句展开用途；禁止长篇「选型心路历程」代替落地  
- 优先段首主题词，忌全局 1.2.3.；局部短列举可接受

### 4.5 结尾

- 上线效果 + 客户评价 + **呼应具体论题**  
- 2 个架构/方法层面的**小不足** + 纠偏思路（忌致命运维事故当主不足）  
- 字数不够多写结尾（可至 500），多了先压结尾再压背景

## 5. 点题链与加粗

**点题链（缺一补一）：**  
摘要后半 → 背景末过渡 → Q2 段首 → 每实践段首 → 结尾呼应论题。

**加粗（机试）：** Q2 要点名、关键指标（QPS/P99/可用性等）、核心架构决策。

## 6. 题型速记

| 题型 | Q2 | Q3 |
|------|----|----|
| 手段类（高并发等） | 逐项定义题面手段（N 全覆） | 按模块或按手段：问题→手段→效果 |
| 风格类 | 风格含义；选定主线 | 构件/连接件/约束 + 项目落地 |
| 方法类（ABSD 等） | 方法步骤/要素 | 需求驱动→文档→复审→演化 |
| 过程类（六边形等） | 分析/设计/实现全流程 | 各阶段在本项目中的动作 |

## 7. 致命禁忌（一票否决级）

1. Q2 专段缺失或答成另一论题  
2. 摘要未点题 / 论题被替换（高并发→微服务架构论等）  
3. 教学小标题腔；通篇全局编号无段落  
4. 背景技术栈子弹、功能只点名不介绍  
5. Q3 不出现题面关键词；无项目模块与效果；列举题漏项  
6. 风格与框架混淆（Vue/MyBatis 冒充架构风格）

## 8. 考场时间盒（120 分钟）

1. 0–10：审题 + **映射表**（见下）+ 主论点  
2. 10–25：摘要 + 背景  
3. 25–90：Q2 + Q3  
4. 90–110：结尾调字数（保证正文小计 2200–2500）  
5. 110–120：子题三刀打勾 + 加粗 + 通读

**映射表最小模板（写前必填）：**

| 子题 | 题面关键词 | Q2 应答要点（列举则列满 N 项） | Q3 段首主题 / 落地模块 |
|------|------------|--------------------------------|------------------------|
| Q1 | … | （背景承载） | — |
| Q2 | … | 1.… 2.… 3.… | — |
| Q3 | … | （须覆盖左列要点） | 段1… / 段2… / 段3… |

## 9. 默认裁决（资料冲突）

| 冲突 | 默认 |
|------|------|
| 摘要 vs 正文 | 摘要另框 ≤300；**正文小计 2200–2500** |
| 「全文 2200」口语 | 多指**正文**；含摘要时口算约 2500–2800 |
| 背景 | 500–600（文老师模板） |
| Q2 | 默认 350–450；列举题可至 500，同时压缩结尾或背景 |
| 实践 | 默认 1000–1200（3 段）；冲刺档至 1500 时禁止其它块同时取上限 |
| 主源「主体 1200」 | = 紧凑档 Q2+实践；Skill **默认档**取 1400–1600 |
| 结尾 | 350–450，调节至正文落在区间内 |
| 编号 | 段首主题句优先；少全局 1.2.3. |
| 背景是否绑题 | 主体通用；过渡与正文贴题 |
| 角色称谓 | 系统架构设计师 |
| 评分框架 | **先**子题三刀 **再**五维 |

## 10. 写前检查清单（浓缩）

1. Q2 是否单独一段且约 350–450 字（列举可至 500，见 §9）？  
2. 摘要 ≤300 且能看出论题关键词？  
3. 背景 500–600，是否展开 2–3 个功能 + 技术用途？  
4. 实践 ≥3 段「在本项目中…」+ ≥3 个量化指标？正文小计是否在 2200–2500？  
5. 无教学标题、无全局 1.2.3.？  
6. 结尾呼应论题 + 2 个小不足？  
7. 给分点是否加粗？  
8. **列举/过程题：题面 N 项是否在 Q2 全覆，且在 Q3 均有对应落地？**
